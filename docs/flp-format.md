# FLP 提取原型格式记录

研究日期：2026-10-28。这里区分样本字节观察、参考实现的格式信息和未验证的播放语义。

## 为什么暂不使用 PyFLP 作为运行依赖

在 Python 3.10.6 中安装 PyFLP 2.2.1 后，对本地研究样本调用 `pyflp.parse()`，
得到 UTF-16LE 解码异常。继续检查原始字节发现：

1. 文件内版本事件为 `25.2.4.5242`。
2. 偏移 `0x30` 的事件 `0xAC` 后面是三个负载字节 `01 01 00`，再后面 `0xC0` 是下一事件。
   将它按 DWORD 读取会吃掉 `0xC0`，导致后续事件错位。错误发生在事件流层，并非简单的坏字符串。
3. 正确处理后共 1828 个事件，事件边界恰好到达文件末尾，7 个真实通道与文件头一致。
4. Playlist 事件 `0xE9` 负载为 1360 字节，可以拆成 17 条 80 字节记录。

独立的格式调查也记录了 3 字节 `0xAC` 特例和 80 字节 Playlist 布局：
[flpdiff 格式调查](https://github.com/dawhubapp/flpdiff/blob/main/docs/fl-format/flp-format-spec.md)。
该资料仍有待验证的描述，原型以本地样本和字段一致性校验为约束，不把整篇文档视作官方规范。

原型为标准库只读实现，不调用 PyFLP 的项目保存方法，不重写输入文件。
本地 `.venv` 和 `.scratch` 是研究用环境/探针，不是运行依赖，也不纳入版本控制。

## 已使用的字段

FLP 文件头保留 PPQ，事件流提供项目和对象数据。关键事件：

| 事件 ID | 原型用途 |
| --- | --- |
| 199 / `0xC7` | ASCII 保存版本，用于选择支持范围 |
| 172 / `0xAC` | FL 25/26 配置中的三字节特殊事件，仅正确跨过负载 |
| 156 / `0x9C` | 文件保存的 BPM × 1000 |
| 64 / `0x40` | Channel Rack 通道 ID |
| 65 / `0x41` | Pattern ID；音符和元数据可分段出现，必须按 ID 合并 |
| 224 / `0xE0` | 24 字节音符记录 |
| 99 / `0x63` | Arrangement ID |
| 233 / `0xE9` | Playlist 片段记录 |
| 238 / `0xEE` | Playlist 轨道元数据 |

音符的音高、位置、时值、力度、声像等字段与
[PyFLP pattern.py](https://github.com/demberto/PyFLP/blob/master/pyflp/pattern.py) 描述的布局一致。
注意步进音符的 length 可以是 0；通道编号属于 Channel Rack，不等于 Playlist 轨道编号。

Playlist 记录前 24 字节包含位置、引用、长度、反向轨道编号和标志。
当前保存格式的轨道编号换算为 `500 - track_rvidx`。
记录后部包含片段标识和额外数据，未解释部分以十六进制保留。
不单凭负载长度可整除就猜测布局：240 同时是 60 和 80 的倍数。

## 裁剪偏移：需要特别区分

本样本最后两个 Pattern 片段的偏移存储不能按 float32 使用。
作为 int32 读取可得到以下一致的源窗口：

| 片段索引 | Pattern | Playlist 起点 | Playlist 长度 | 源起点 | 源终点 |
| --- | --- | --- | --- | --- | --- |
| 15 | 4 | 6144 | 1344 | 1536 | 2880 |
| 16 | 5 | 6144 | 1536 | 0 | 1536 |

单位都是 tick。两条记录均满足 `源终点 - 源起点 = Playlist 长度`。
如果把 1536 的位模式解释成 float，会得到约 `2.15e-42`，音符就会错误地从 Pattern 开头展开。
原型使用整数源窗口，并保留原始位模式以便复核。
未裁剪 Pattern 片段使用 `FFFFFFFF`（有符号 -1），不是一个真正的 NaN 时间。
音频/自动化通道片段不套用 Pattern 的整数时间解释。

这验证的是字节值和几何一致性，尚未在 FL GUI 中逐个比对所有裁剪/缩放/循环操作。

## 计数与验收边界

原始 Pattern 音符数量分别为 `16, 32, 16, 39, 152, 100`，合计 355。
普通完整放置贡献 774 条记录，最后两个裁剪片段贡献 98 条，合计 872。
每个展开音符都能通过 Arrangement、clip_index、pattern_id、note_index 回溯原始来源。

输出将长度和可见交集分开，避免把裁剪边缘当成确定的 note-off；
没有使用波形、没有渲染插件、没有验证听觉等价性。
FL 26 的合成夹具只验证本实现的格式分支，不替代真实 FL 26 文件测试。

## 采样工程副本的实际渲染验证

已用本机 FL Studio 26.1.7.5654 的命令行加载并渲染本工具生成的工程副本，未使用界面自动化。
准备采样工程时保持 Pattern 的 looped 关闭；开启它会造成通道内额外重复触发。
FL 命令行可能忽略拉长片段后的纯空白尾部，因此在空的、禁用的 Sampler 上放置末尾定位音符，
明确采样工程终点。该定位音符不属于导出键音，既没有采样资源，也不启用通道。

样本中的 FLEX 状态包含 `Black Octopus Atlantis` 包名，本机缺少对应 `.flexpack`。
在副本中将该通道中和为空 Sampler，保留其 100 条 Playlist 音符为标准 MIDI 和 JSON；
其余通道的 128 个键音通过自适应尾音重试生成，覆盖 772 次原曲触发。
尾音窗口根据实际包络/静音检查调整；到达配置的尝试或时长上限时明确失败，不强制裁断。

资源检查只读取已知文件路径和状态结构。FLEX 默认用户包位置参考
[Image-Line FLEX 手册](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/plugins/FLEX.htm)，
命令行参数参考 [Image-Line 导出文档](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/fformats_save_export.htm)。
未知第三方插件内部库、授权状态和复杂播放交互不视为已验证。
